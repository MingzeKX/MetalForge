### 3.1 截图过程中的发现（每条都是真实缺陷，已修复）

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | 截图右侧整块面板消失 | `GetWindowRect` 返回物理像素，直接喂给 `CopyFromScreen`，在 150% 缩放下坐标错位 | 改用 `GetClientRect` + `ClientToScreen`，并按真实帧缓冲尺寸裁剪 |
| 2 | 应用窗口超出屏幕 | 默认 1440x900 逻辑像素在 150% 缩放下占 2160x1350 物理像素 | 默认降到 1280x720；新增 `Opened` 后的 `ClampToScreen` 二次钳制 |
| 3 | 平台报告的屏幕尺寸大于真实帧缓冲 | 本机 2256x1504 vs 实际 1280x720（远程/虚拟显示环境特性） | 新增 `FramebufferProbe`（Win32 `GetSystemMetrics`）参与钳制；口径不一致时以更小者为约束 |

> 说明：现象 3 中两个独立来源（Avalonia 平台 API 与 Win32）报告一致，只有截图进程看到更小的
> 帧缓冲，属于当前会话显示环境的特性。应用侧的钳制逻辑保留，用于对"OS 报告不可信"免疫。

## 4. 配置热重载（端到端，已脚本化）

```powershell
.\scripts\Verify-HotReload.ps1
```

实测输出：

```
[1/5] Launch app and wait for initial configuration load
    OK   startup log observed
[2/5] Change branding name via assets/branding/app.json
    OK   branding change triggered a reload
[3/5] Change theme palette via assets/themes/metalforge-dark.theme.json
    OK   theme change triggered a reload
[4/5] Write malformed JSON and confirm graceful degradation
    OK   malformed JSON produced diagnostic MFCFG143
    OK   app still running after bad configuration (degraded, not crashed)
[5/5] Restore files and verify the repository was never touched
    OK   repository assets unchanged

HOT RELOAD VERIFICATION PASSED
```

脚本验证的四件事（都是单元测试覆盖不到的部分）：

1. `FileSystemWatcher` 对真实文件保存真的会触发；
2. 变更真的到达 UI 线程并刷新（日志事件 1102）；
3. 主题文件变更同样触发重载；
4. JSON 写坏时应用**降级继续运行**而不是崩溃，并产出 `MFCFG143`（带行号列号的语法错误诊断）。

脚本只修改 `build/` 输出目录下的 `assets/` 副本，并在 `finally` 中还原；仓库 `assets/` 不会被改动
（脚本会检查 `git status -- assets` 并报告）。

> 实现注记：stdout 被重定向到文件后，该文件由子进程持有，无法删除或截断。
> 因此脚本按**字节偏移增量读取**日志，而不是每次清空文件重读。
