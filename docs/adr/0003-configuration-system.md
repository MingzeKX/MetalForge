# ADR-0003：三级 JSON 配置 + 来源追踪 + 热重载，全部元信息配置化

- **状态**：已接受
- **日期**：2026-02
- **相关**：DESIGN.md §11 配置系统设计、§六 元信息配置化

## 背景

项目要求：关于对话框、版本信息、应用图标、启动画面、配色主题、布局预设、许可协议、
更新日志、贡献者名单，全部由 `assets/` 下的 JSON 与资源文件驱动，不得硬编码在 C# 里；
并要求非程序员能通过编辑 JSON 修改品牌信息、新增配色主题、调整默认布局。
同时要求配置错误时回退默认值并提示用户，而不是崩溃。

这三条要求（可外部编辑 / 不崩溃 / 可提示）会互相拉扯：外部可编辑意味着文件随时可能是坏的，
不崩溃意味着不能抛异常，可提示意味着必须知道"坏在哪里"。

## 决策

### 1. 三级覆盖，语义刻意保持简单

```
内置资源（assembley 内 / 发布目录 assets/）  ←  用户目录（%APPDATA%\MetalForge 或便携模式）  ←  项目目录（<project>/.metalforge/）
```

合并规则：

| 情况 | 行为 | 理由 |
|---|---|---|
| 对象 | 深合并，逐字段覆盖 | 用户只想改一个字段时不必复制整份文件 |
| 数组 | **整体替换** | 元素级合并会产生"看起来生效了一半"的结果，用户无法预测 |
| `null` | 删除该键，回落到下一层或默认值 | 提供"恢复默认"的表达能力 |

### 2. 每个叶子记录来源层级

`ConfigurationMerger` 在合并时同步生成 `JSON Pointer → 生效层级` 映射（`ConfigOrigin`），
UI 可据此显示"此值来自项目配置"。被 `null` 删除的键会连同来源一起清理，避免给出过期来源。

### 3. 任何一层失败都不阻断启动

- 文件语法错误 → 该层被忽略，其余层继续生效，产出带**行号列号**的诊断；
- Schema 校验失败 → 报告未知字段/类型错误/取值越界，带 JSON Pointer 与修复建议；
- 文件不可读 / 无权限 → 转为诊断（携带原始异常），不抛出；
- 内置资源全部缺失 → 使用编译期兜底值并记录严重诊断（这是唯一允许的硬编码后备）。

### 4. 热重载

`FileSystemWatcher` 监视三层目录，300ms 防抖（编辑器一次保存会触发多个事件），
重新加载时先构建完整新快照再原子替换引用；UI 更新经 `Dispatcher.UIThread.Post` 切回 UI 线程。
热重载自身失败时保留上一份可用快照，并把失败作为诊断暴露。

### 5. 主题的两个配套约束

- Core 的 `ThemePalette` 字段**全部可空且无默认颜色值**。理由：只要 Core 里写了一套调色板默认值，
  "JSON 是唯一真相源"就变成了空话 —— 用户删掉主题文件后界面照样有颜色，没人会发现配置没生效。
- 相应地，`ThemeResourceService` 在颜色缺失时填入透明画刷，让问题在界面上可见，
  并由 `ConfigurationServiceTests.BuiltInThemes_AllHaveUniqueIdsAndParsableColors`
  断言"解析后的主题不得有缺失颜色键"。
- 约束由 `NoHardCodedVisualsTests` 强制：扫描 `src/**/*.{cs,axaml,json}`，
  出现颜色字面量（`#RRGGBB`、`#AARRGGBB`）或 `Colors.Xxx` 即测试失败，
  白名单仅 `ThemeResourceService.cs`（颜色值 → 画刷的唯一转换边界）。

## 后果

**正面**
- 改品牌名、换主题、加主题文件都不需要重新编译，实测保存后立即生效。
- 配置错误对用户是可读的：`branding/app.json/taglin: [Error] MFCFG103: 未知字段 'taglin'。可用字段：...`
- 全部逻辑在 Core 中，73 个测试覆盖配置合并、Schema 校验、错误回退、主题派生。

**负面 / 权衡**
- 数组整体替换意味着"只想在布局里加一个工具栏按钮"必须复制整个数组。这是刻意换来的可预测性。
- `extends` 派生主题只解析两轮，超过两层的继承链不会继续展开（避免循环继承导致无限递归）。
  实际场景（高对比度派生自默认深色）一层足够。

## 备选方案

| 方案 | 否决原因 |
|---|---|
| 只用单一配置文件 | 无法区分"发行默认值"与"用户改动"，升级时必然覆盖用户设置 |
| 用环境变量/注册表做主配置 | 非程序员无法愉快编辑；项目级配置无处安放 |
| 数组也做元素级合并 | 语义不可预测（按索引？按 id？），调试成本高 |
| 配置解析失败时抛异常 | 与"配置错误回退并提示"的要求直接冲突 |
| Core 里保留一套默认调色板 | 会让"配置化"名存实亡，见上文 §5 |
